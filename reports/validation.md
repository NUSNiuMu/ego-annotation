# 独立流程提取验收 · 2026-11-05

范围：本地 MCAP 输入、JPEG 采样、Qwen 双输入调度、文本审理、按需图审、结果保存。
独立包名 `ego_annotation`，唯一业务入口 `ego-annotate`。

- 80 项测试通过：真实合成 MCAP 解码、时间/帧映射、双输入补位、窗口断点恢复、
  局部失败隔离、坏窗口强制图审、完成结果复用、证据被改动时拒绝继续。
- 审核验证包括成功调用落盘后中断的恢复，以及真实子进程、附件哈希、返回码和
  禁止模型工具调用的回执链。Qwen/GPT 使用明确标记的测试替身，不是新任务语义验收。
- 独立 Python 3.10 虚拟环境安装通过；该环境允许读取系统包，基础 MCAP/PyAV/Zstandard
  使用原始缓存 wheel 安装，未依赖原项目的 Python 模块。安装后重跑 80 项仍通过。
- 安装后的 `ego-annotate --help`、实际合成 MCAP 的 `--prepare-only` 和 wheel 构建通过。
- 没有连接、部署或启停原生产服务，没有占用生产 GPU，没有调用付费模型。

保留来源流程的模型数值实现；针对交付修改了包命名、本地调度、运行配置和 GPU UUID
查询，去掉 NAS/READY 收发、生产执行权、下游清理与发布依赖。
完成任务核验后只读复用，避免改写审核 packet 固定的 `job/status` 哈希。
时间跨度和窗口数量检查复用已经读出的头信息，不添加第二遍 MCAP 扫描。

来源与提取文件哈希见 [extraction.json](extraction.json)。来源为当日工作树快照，
不冒充来源仓库某个已提交版本。原始测试日志保存在交付方忽略的 artifacts 中，未推送。

叠衣服 policy、动作表、两个 skills 和单相机 topic 作为示例原样保留。
其他任务、输入格式、视角对齐、GPU/驱动和账号模型权限由接收方适配验收。
没有进行新机器上的 Qwen/GPT 实际推理，也没有把测试平滑或结构通过当作标注质量证明。
